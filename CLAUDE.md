# CLAUDE.md — SKYNET

SKYNET is a fork of God's Eye View (Vite + vanilla JS + CesiumJS, Node proxy
server). The build brief is `SKYNET_CLAUDE_CODE_PROMPT.md`; the design and phase
plan are `docs/ADR-001.md`. Upstream conventions still apply: read
`CONTRIBUTING.md`, `docs/I18N.md` and `docs/CODE-BOUNDARIES.md` before changing
code.

## Operating rules

- **Plan before code.** Work one phase of `docs/ADR-001.md` at a time; run that
  phase's acceptance checks and report them before starting the next.
- **Never claim something works unless you ran it.** Report exact commands and
  outputs; say plainly what was not verified.
- **Token-efficient edits:** targeted reads and Grep over whole files; edits
  over rewrites.
- **Additive and reversible.** Keep God's Eye View features working. New
  capabilities sit behind a layer or panel toggle; turning one off restores the
  prior behaviour. Keep the diff to upstream files small (registration points
  only) so `git merge upstream/main` stays tractable.
- **Ask a two-line question** when a missing answer would change architecture;
  otherwise state the assumption and proceed.
- **No stubs presented as features.** A feature works end to end or is visibly
  disabled with the reason in the UI.
- Commands are PowerShell-compatible (Windows 11); say which terminal runs them.

## Hard lines

- No named-person search, face recognition or tracking of individuals. SKYNET
  models events, assets, infrastructure and systems.
- Not for navigation, emergency response or other safety-critical use; keep the
  disclaimer visible.
- No shell, file or code-execution tools are ever exposed to a model.

## Licensing and data

- MIT covers code only. Never bundle non-commercial or restricted data in the
  default build; fetch at runtime or make it an opt-in download.
- Personal-use-only APIs go behind the Non-commercial sources switch
  (`server/providers/common/non-commercial.js`, off by default).
- Register every new source in `src/data/dataCredits.js` and `DATA_SOURCES.md`.
  Keep the on-globe Google, Cesium and Esri credits and the Data attribution
  link visible at all times.
- News: store headline, short summary, source, URL and timestamp only.

## SKYNET conventions

- **Branding:** every product name, tagline and brand colour comes from
  `src/branding.js`; outbound requests use `brandUserAgent()`.
  `src/branding.test.mjs` fails if a shipped page names the upstream product.
- **Theme:** `src/theme/skynet.css` (tokens, loaded last from `index.html`) and
  `src/theme/skynet-recolor.css`, generated by
  `node scripts/generate-skynet-recolor.mjs`. Re-run it after any change under
  `src/ui/styles/`; a test fails when it is stale. Keep text WCAG AA.
- **UI text** goes through `t()` / `msg()` with es and ru translations
  (`npm run i18n`).
- **Commit flow:** conventional commits; before committing code run
  `npm test`, `npm run check:boundaries`, `npm run format:check` and, for
  build-affecting changes, `npm run build`.
- **Intel service** (`intel/`, Python 3.12 via uv): before committing run
  `uv run --project intel pytest intel/tests` and, from `intel/`,
  `uv run ruff check .` and `uv run ruff format --check .`. Tests never touch
  the network (a conftest guard fails any non-loopback connection) or
  `intel/data/`. Schema changes are new numbered files in
  `intel/app/store/migrations/`; never edit an applied one. A new feed goes in
  `intel/feeds.default.yaml` only after `intel/scripts/verify_feeds.py` passes
  it, and only as `terms: open` when its reuse terms were actually checked.

## Test baseline

`npm test` has one known environmental failure on this machine:
`src/tooling/skyAssets.paintOut.test.mjs` (the space in the Windows user path
becomes `%20`). `src/sdr/decoderDiagnostics.test.mjs` can flake under
full-suite load and passes alone, as does `src/data/geoFileImport.test.mjs`
("repeated incomplete KML roots finish within an isolated process deadline",
a 5 s wall-clock budget). `src/terrainHeightsBounds.test.mjs` fails
("1 !== 2") once a dev server has written `.gev-cache/terrain-heights.json`,
because the test reads the real cache; it passes with that file moved aside.
Anything else failing is a regression.

`npm run test:track` (needs `npm run dev` on port 4173) fails the "arrival:
moveEnd + first reveal" check at its 500 ms deadline under headless software
GL on this machine; upstream fails it the same way.
