## 2. Decisions

### D1. Merge strategy: GEV is the trunk, WM v2 is a logic donor

- SKYNET is a git fork of GEV in `C:\Users\Murali Kannan\Workspace\Claude\SKYNET` with remote `upstream` (already set). Upstream history is preserved so future upstream fixes can be merged.
- **Keep the diff to upstream files small.** New code goes into new directories. Upstream files change only at registration points:
  - the plugin list, layer catalog, panel groups and credits;
  - the branding template hooks;
  - the CSS import list.

  This keeps periodic `git merge upstream/main` tractable against a fast-moving upstream.
- WM v2 is read-only. Logic is re-implemented in GEV's idioms: vanilla JS with Prettier and the boundary rules, or Python in `intel/`. No React, Tailwind or Zustand comes across.
- **Compatibility identifiers stay:**
  - `GEV_*` env vars;
  - localStorage keys;
  - `.gevbundle.json`;
  - the `gods-eye-view` package name, which 9 tests use.

  These are not user-visible. Renaming them would break user state and tests for no user benefit.

### D2. Service split: one browser origin, Python behind it

```
Browser (Cesium, GEV UI, News layer, Neural Core panel)
   │  same-origin only (CSP)
   ▼
GEV Node/Vite server  http://localhost:4173   (unchanged providers + NEW server/providers/intel.js)
   │  /api/intel/*  → streaming reverse proxy (SSE unbuffered, client aborts propagated)
   ▼
SKYNET intel (FastAPI, uvicorn)  http://127.0.0.1:8100
   ├─ ingest (RSS/Atom, GDELT) → dedupe → geoparse → classify → SQLite+FTS5
   ├─ chat agent loop → Ollama http://127.0.0.1:11434 (/api/chat, tools, stream)
   └─ web: SearchProvider (ddgs | searxng | brave | tavily) + fetch_page (SSRF-guarded)
```

- `server/providers/intel.js` is modelled on `server/providers/transit.js` and registered in `localProviderPlugins()`, so it runs before `apiNotFoundPlugin`. The browser **never** talks to Ollama.
- If the intel service is down, the proxy returns `503 {"state":"intel_offline"}`. Every SKYNET surface then shows an offline state, and GEV keeps working unchanged.
- Everything binds to `127.0.0.1`. GEV's LAN-sharing opt-in, with its warnings, is unchanged. If LAN sharing is on, `/api/intel/chat*` stays **localhost-only** unless separately opted in.
- `scripts/skynet.ps1` starts both processes with one command: it creates the uv venv on first run, starts uvicorn, then `npm run dev`. Native start is primary. `compose.yaml` gains an optional `intel` service; Docker is not installed on this machine, so compose must never be required.
- Python: CPython **3.11 or 3.12** via `uv`. Both 3.11.15 and 3.12.10 are present. 3.14 is the system default, but it is not used because spaCy wheels lag new Python releases.

### D3. Intel data model

SQLite in WAL mode at `intel/data/skynet.db`, gitignored. Migrations are numbered SQL files (`intel/app/store/migrations/0001_init.sql`, ...) applied by a ~40-line runner that records `schema_migrations(version, applied_at)`.

This deviates from Alembic on purpose. Alembic brings SQLAlchemy, and its autogenerate does not model FTS5 virtual tables or triggers. Plain SQL keeps the FTS5 DDL explicit and testable. The migration *style* (ordered, immutable, versioned) is kept.

| Table | Key columns |
|---|---|
| `feeds` | id, url, name, category, region, enabled, terms_note, etag, last_modified, last_success_at, last_error, consecutive_errors, next_poll_at, item_count |
| `stories` | id, title, summary (≤ 400 chars), canonical_url, url_hash (unique), published_at, first_seen_at, updated_at, category, severity, lat, lon, geo_confidence, place_name, country_code, source_count |
| `story_sources` | story_id, feed_id, source_name, url, title, published_at (one row per outlet in a cluster) |
| `news_fts` | FTS5 (external content = `stories`: title, summary, place_name), BM25, sync triggers |
| `conversations` / `messages` | chat history: role, content, tool_calls_json, citations_json, created_at; "clear history" deletes both |
| `tool_log` | ts, conversation_id, tool, args_json, status, duration_ms, url; **no fetched content** |

- Indexes: `stories(published_at)`, `stories(category)`, `stories(lat, lon)`.
- Retention: 30 days by default, configurable.
- Only headline, short summary, source, URL and timestamp are stored. **No article bodies**, as required by brief §2.

### D4. News pipeline

- **Feeds.** WM v2's 3 feeds are not enough, so `intel/feeds.default.yaml` is curated new in Phase 2. It covers world, regions, defence, cyber, science, economy, disasters and space.
  - Prefer open publishers whose terms allow it: UN News, ReliefWeb/OCHA, WHO, USGS, NASA, ESA, NOAA, CISA and similar.
  - Record a `terms_note` per feed, and flag publishers whose RSS terms say "personal use".
  - `intel/scripts/verify_feeds.py` must see HTTP 200, a parse, and at least 1 item for every URL. Failures are dropped and listed in the report.
  - **GDELT DOC 2.0** is enabled by default, can be switched off, and carries its required citation and link. **Google News RSS is never a default.**
- **Polling.** Async scheduler, 5 min per feed by default, ETag/If-Modified-Since, jittered exponential backoff (max 1 h). Per-feed health is exposed at `/api/intel/health`.
- **Dedupe.**
  - Canonical URL: lowercase host, strip `utm_*`/`fbclid`/fragment, resolve `amp` variants; then sha1.
  - Title similarity: rapidfuzz `token_set_ratio` ≥ 88 within 48 h clusters matching items into one story with several `story_sources`.
- **Geoparsing.** spaCy `en_core_web_sm` (MIT) extracts `GPE`/`LOC`/`FAC` entities. They are matched against a bundled gazetteer built from GeoNames `cities15000` + `admin1` + `countryInfo` (CC BY 4.0, attributed).
  - Disambiguation uses population, country co-mentions in the item, and feed region.
  - A `geo_confidence` in [0, 1] is stored. Only items at ≥ 0.6 appear on the globe; all items appear in the panel and ticker.
  - **No per-item Nominatim calls.** That is forbidden by its policy.
- **Categorization.** WM v2's keyword classifier, extended, runs first and is deterministic. Optional batched LLM tagging sits behind a setting and runs after ingest. It never blocks ingest.
- **API.**
  - `GET /api/intel/news` (q, since, until, category, region, source, bbox, limit, cursor)
  - `GET /api/intel/news/stream` (SSE `story` events plus a heartbeat every 15 s)
  - `GET /api/intel/news/{id}`
  - `GET /api/intel/health`

  `docs/API.md` points at FastAPI's generated OpenAPI. The frontend is built against it.
- **Freshness UX.** "updated X min ago" everywhere, and a stale badge past 3× the poll interval.

### D5. Neural Core: agent loop on the server, globe tools in the browser

- **Loop location.** `intel/app/chat/agent.py` calls Ollama `/api/chat` with `stream:true`, `tools`, `think:false` (configurable), `keep_alive:"5m"` and `num_ctx` from settings (**Q4**).
  - At most **4 tool iterations** per turn.
  - Capability check: `/api/show` must list `tools`. If not, use constrained-JSON fallback (`format` = tool-call JSON schema) and show **"degraded: no native tools"** in the panel.
- **Client-tool round trip.** Globe tools must run in the browser, through GEV's existing dispatcher.
  1. The server emits SSE `client_tool {turn_id, call_id, name, args}`.
  2. The panel validates the arguments against the schema and runs the call via the same path `withToolCatalog` uses.
  3. The panel POSTs `/api/intel/chat/tool-result {turn_id, call_id, ok, result}`.
  4. The server waits up to 15 s, then gives the model a timeout error. The call counts toward the 4-iteration cap.
- **Map context, no round trip.** Each user message carries a `viewport` snapshot (camera, bbox, time) and a `layer_state` snapshot (active layers and options). The server injects them into the system prompt every turn and answers the `viewport()` and `layer_state()` tools from them.
- **SSE events:** `token`, `tool_status` ("searching…", "reading example.com…"), `client_tool`, `citation`, `done {model, tokens_per_s, eval_count, as_of}`, `error {code, message}`.
- **Panel header readout, from real data only:**
  - model name;
  - load state, from `/api/ps`, polled while the panel is open;
  - tokens/s, from `eval_count / eval_duration`.

#### Single source of truth for tool schemas

Client tools are defined in JS and server tools in Python. Each side exports the same JSON (OpenAI function format) into one committed artifact, `shared/tools/neural-core.tools.json`. A generator, `npm run tools:export`, writes the client half from `src/tools/registry.js`. A Python test asserts that the server half matches `intel/app/chat/tools.py`, and a JS test asserts that the client half matches the registry.

- **Python** reads the artifact to allowlist the client-tool names and schemas it will relay. The browser cannot inject new tools.
- **The MCP server and voice providers** read the same artifact. OpenAI Realtime wants the flat format and Ollama wants the `{type:'function', function:{}}` wrapper. `scripts/voice-bench/toolFormats.mjs` already converts between them and will be lifted into `src/tools/`.
- **Tool descriptions** currently sit in server-only Node files. They move into a pure, browser-safe module under `src/voice/` so the registry can import them without breaking `check:boundaries`.

#### Tool subset and context budget

The full catalog is about 15k tokens and does not fit. Neural Core exposes a curated subset.

- **About 12–15 globe tools:** fly-to/place, toggle layer, set map style, sensor/visual mode, track/follow, annotate/mark, measure, reset view, set time, and a few catalog queries such as `next_satellite_pass` and nearby quakes.
- **Server tools:** `news_search`, `news_near`, `web_search`, `fetch_page`, `layer_state`, `viewport`.

Budget at the recommended `num_ctx` of 16384:

| Slice | Budget (tokens) |
|---|---|
| System prompt and policies | ≤ 800 |
| Viewport and layer state | ≤ 400 |
| Tool schemas | ≤ 3,000 (measured at build; a test fails above it) |
| Trimmed history | ≤ 3,000 |
| Wrapped web/news results per turn | ≤ 6,000 total; `fetch_page` returns ≤ 2,500 tokens of text per page |
| Generation headroom | ≥ 2,000 |

In low-resource mode (`num_ctx` 8192), the history budget drops to 1,500, the web budget to 2,500, and `fetch_page` is capped at 1,200 tokens.

#### Web check

- `SearchProvider` implementations:
  - `ddgs`: keyless default, best-effort, rate-limited, shown as such;
  - `searxng`: user URL, recommended;
  - `brave` / `tavily`: key in `.env` or Provider Settings.

  Provider status appears in Settings and in `doctor`.
- `fetch_page` uses httpx with a custom transport.
  - **SSRF guard.** Resolve DNS once, reject private, loopback, link-local, CGNAT, multicast, reserved and IPv4-mapped IPv6 ranges, then **connect to the validated IP** with Host/SNI set. This defeats DNS rebinding.
  - **Scheme and port:** http(s) only, ports 80 and 443 only.
  - **Redirects:** at most 3, each fully re-validated.
  - **Limits:** robots.txt respected, 10 s timeout, 1 MB cap; only text content types are extracted, via trafilatura.
- **Prompt-injection defence.**
  - All fetched or searched text is wrapped as `<untrusted_web_content source="…">`, and the system prompt states it is data.
  - Tool calls are schema-validated server-side regardless of what preceded them.
  - Every tool call and fetched URL is logged to `tool_log` and `.skynet-logs/` (gitignored), with no content.
  - **No shell, file or code-execution tools exist.**
- **People are not a query type.** This is GEV's line (`README.md:631`): no features for named-person search, face recognition, or tracking individuals. `web_search` and `fetch_page` would make a "find this person" request easy, so the system prompt refuses to look up or locate private individuals and refuses to track people. The server also rejects `news_near` and `web_search` calls whose stated purpose is locating a named private person. The answer policy covers events, assets, infrastructure and systems; public figures appear only as they occur in news about events.
- **Answer policy.**
  - Questions about the latest or current state of things are always searched first.
  - Answers carry numbered citations `[n]` linked to the URL and end with `As of <local time>`.
  - When search fails or returns nothing relevant, the model says so instead of answering from memory.
  - Conflicting sources are named.

### D10. Model defaults and low-resource mode

- **Default chat model:** `bonsai-2:9b` (**provisional**).
  - The probe passed 5/5, it runs 100% on GPU, and it uses 3.4 GB at 16k context.
  - It is re-probed in Phase 4 with the real tool subset and page-sized context, and the 15-prompt eval decides.
- **Quality option:** `qwen3.5-9b-64k-gpu`. It is too large to run fully on the GPU at 8k context (15% CPU offload).
- **Settings:** `OLLAMA_HOST`, `OLLAMA_MODEL`, `OLLAMA_NUM_CTX`, `OLLAMA_KEEP_ALIVE` in `.env`, with the same fields in Settings. The model picker lists `/api/tags` filtered to models that report the `tools` capability; `:cloud` tags are hidden unless the user opts in.
- **Low-resource mode:** `num_ctx` 8192, the smallest tool-capable model, a reduced tool subset, and reduced layer density (GEV's existing density and LOD knobs).
- **Phase 4 outcome (2026-10-27):**
  - **Default model.** The eval (`docs/phase4/neural-core-eval.md`) chose `qwen3.5-9b-64k-gpu:latest` as the default: 14/15 and 15/15, with no model errors. `bonsai-2:9b` scored 12/15 and 13/15, missing citations and once not searching.
  - **Low-resource mode.** `SKYNET_LOW_RESOURCE=1` gives `bonsai-2:9b`, `num_ctx` 8192 and the smaller history, web and page budgets.
  - **Not built yet.** The in-app model picker and Settings fields (models are set in `.env` for now), and low-resource mode's reduced tool subset and layer density.

### D11. Local voice (Phase 5 outcome, 2026-10-28)

- **Where it lives.** A push-to-talk mic button in the Neural Core panel.
  - The transcript is sent as an ordinary chat turn, so the person-lookup refusal, the rate limit and the tools all apply unchanged.
  - GEV's OpenAI and Gemini voice providers are untouched (`src/voice/` has no changes).
- **Engines.** faster-whisper `base` (int8) and Kokoro-82M (int8 ONNX), each on 8 CPU threads.
  - The GPU stays with the chat model.
  - A probe on this machine chose `base` over `small`: 0.84 s against 2.06 s for a 4 s question, with no accuracy gain on the test clips.
  - Kokoro rather than Piper: Kokoro's weights are Apache-2.0, while `piper-tts` is GPL-3.0 itself.
- **Opt-in install.** `scripts\skynet.ps1 -Voice` installs the intel `voice` extra and fetches about 270 MB of pinned models, each checked against its SHA-256.
  - kokoro-onnx pulls in phonemizer and espeak-ng, which are GPL-3.0. They are never installed by default or shipped (NOTICE.md).
- **Behaviour.**
  - Answers are spoken sentence by sentence as they stream, with at most two speech requests out at once.
  - Stop, a new press or closing the panel silences the answer.
  - Spoken replies are English only.
  - Audio is never stored or logged.
- **Measured.** Median from button release to the first spoken word (`docs/phase5/voice-latency.md`): 4.7 s for a news-store question, 6.5 s for a globe action and 11.2 s for a web question. Whisper takes about 1 s of each; the model and its tools take most of the rest.
- **Not built.**
  - Wake word or continuous listening; speaking over the answer to interrupt it.
  - Non-English spoken replies.
  - Speech on the GPU.
  - A local entry in GEV's voice provider picker.

### D12. Keyless default basemap (Phase 6 release gate, 2026-10-28)

- **The gate.** Q1(a) kept Esri World Imagery as the keyless development default, with a Phase 6 gate: read Esri's terms and switch the default to NASA GIBS if keyless third-party use is not clearly allowed.
- **Finding.** World Imagery is licensed under the Esri Master Agreement. Esri's summary of its terms for Esri-owned ArcGIS Online items (`tou_summary.pdf`, last updated 2025-04-21) allows use "in conjunction with Esri software or an ArcGIS Online subscription", says that without Esri software "you must purchase an ArcGIS Online subscription", and forbids redistributing tiles. SKYNET uses the service keyless from Cesium, which is not Esri software, so keyless third-party use is not clearly allowed. This is a reading of the terms, not a legal opinion.
- **Decision (owner, 2026-10-28).** The keyless default is NASA Blue Marble (`BlueMarble_ShadedRelief_Bathymetry`) from GIBS: NASA imagery, cloud-free, but only to zoom 8 (about 600 m per pixel), so city close-ups are soft. GIBS's sharper global layers were rejected: the daily VIIRS and MODIS true colour has clouds and gaps, and the 30 m Landsat WELD composites end in 2000.
- **Esri stays a choice.** Its chip states its terms; share links that name it still open it. Upstream's imagery comparison and two scene-director shots still switch to Esri for high-resolution before-and-after views, which the person starts themselves.
- **Unchanged.** With a Google key or ion token the default is still Google 3D. OSM remains the automatic fallback.

| Risk | Likelihood / impact | Mitigation |
|---|---|---|
| Upstream churn (very active repo) causes merge conflicts | High / medium | D1 small-diff rule; registration-point edits only; merge upstream at each phase boundary |

| Context overflow: 54 tools ≈ 15k tokens | High / high | Curated subset plus the budget table in D5; a build-time test fails if schemas exceed 3,000 tokens |
| Q2_0 model answers poorly (citations, synthesis) even though tool selection passed | Medium / high | Phase 4 eval decides; qwen3.5 as the quality option; never claim quality we did not measure |
| GPU contention if the browser uses the RTX GPU | Low by default (measured iGPU) / medium | Document Windows Graphics settings; `doctor` reports VRAM via `nvidia-smi` when present; low-resource mode |
| Prompt injection via fetched pages | Medium / high | Delimiters, data-not-instructions policy, server-side schema validation, client-tool allowlist, no dangerous tools, logging |

| Keyless sources rate-limit or change terms (ddgs, GDELT, adsb.lol keys, Photon, OSM tiles) | High / medium | Per-provider health and visible degraded states; SearXNG recommended; adsb.lol feeder-key field ready |

| Windows pathing (spaces in the user path already break one upstream test) | Medium / low | Use `fileURLToPath` and `pathlib` everywhere in new code; run every test from this path |
| spaCy and Python version friction on Windows | Medium / medium | Pin Python 3.11/3.12 via uv; pin spaCy and its model; `doctor` checks them |
| **Name "SKYNET" (and WM v2's "Cyberdyne Systems") are names from the *Terminator* franchise** | Unknown / medium for a public release | Not a legal opinion. `src/branding.js` makes a rename a one-file change. Decide before a public v0.1.0 |
